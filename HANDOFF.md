## Ключевые решения по ходу сессии (расхождения с исходным ТЗ)

- **Тон сообщений расширен по просьбе пользователя**: у каждого сообщения бота точка в конце +
  один уместный эмодзи (💸 расход, 💰 доход, 🔄 перевод, 💳 источник, 🗂 категория, ⚖️ баланс и т.д.).
  Это поверх исходных правил тона из ТЗ (никакой оценочной лексики и т.п. — это осталось в силе).
- **Комментарий стал обязательным** для расхода и дохода (кнопка «Пропустить» убрана целиком) —
  явное решение пользователя: «лучше любой комментарий, чем без него». В исходном ТЗ комментарий
  был опциональным — это осознанное отклонение.
- **Промпты выбора источника различаются по флоу**: расход → «Источник списания», доход →
  «Источник зачисления», перевод → оба на разных шагах. Раньше везде было одинаковое
  «Выберите источник», путало.
- **Постоянное reply-меню снизу чата** (`willem/bot/keyboards.py: build_main_menu`) — кнопки
  «Перевод», «Категории», «Источники». Отправляется в `/start`. Не было в исходном ТЗ, добавлено
  по запросу — команду `/transfer` неудобно печатать руками.
- **Лимит категории — по валюте операции, не абсолютный**: `sum_expenses_by_category` фильтрует
  по `currency`, то есть если категория "Быт" получает траты и в KZT (с Kaspi), и в RUB (с Т-банка),
  суммы не складываются друг с другом — лимит проверяется отдельно для каждой валюты. Это моё
  решение (в ТЗ не описано, там только правило "не складывать валюты" для балансов источников;
  я применила ту же логику к лимитам категорий). Стоит проговорить с пользователем, насколько это
  ожидаемое поведение, когда дойдёт до реального мультивалютного использования одной категории.
- **Новый тип операции `adjustment`** (`willem/db/transactions.py`) — коррекция остатка источника.
  Не было в исходном ТЗ. Нужен был способ вручную выставить фактический баланс источника
  (пропущенные операции и т.п.), не создавая fake-расход без категории. `amount` может быть
  отрицательным (это единственный тип, где так) — это дельта, а не абсолютная сумма.
  `get_source_balance` учитывает этот тип в формуле.
- **Мультипользовательность**: изначально бот был жёстко на одного `OWNER_TELEGRAM_ID`. По запросу
  добавлена подруга — сделан полноценный рефакторинг, не быстрый хак:
  - `Config.allowed_telegram_ids: tuple[int, ...]` = `OWNER_TELEGRAM_ID` + `ADDITIONAL_TELEGRAM_IDS`
    (новая переменная окружения, через запятую)
  - `AllowedUsersMiddleware` (было `OwnerOnlyMiddleware`) проверяет вхождение в список, а не
    равенство одному id
  - **Все хендлеры теперь используют реальный `message.from_user.id` / `callback.from_user.id`**
    как `user_id` в БД, а не `config.owner_telegram_id` — то есть у каждого разрешённого
    пользователя полностью свой леджер (источники/категории/транзакции), данные не пересекаются
  - Сидинг дефолтных категорий/источников (`bootstrap.py`) остаётся **только для владельца**
    (`config.owner_telegram_id`) — это персональные данные (Kaspi, bcc, Артемида и т.д.), их не
    нужно клонировать другим пользователям. Дополнительные пользователи стартуют с чистого листа
    и добавляют свои источники/категории через `/sources`, `/categories`
